## The "levels missing on mobile" issue (resolved)

Root cause, confirmed by Elroy ("when I saved in the browser I saw them on my phone again"):
the TradingView **mobile app has no userscript and no ATAS backend**. It only ever loads the
**server-saved chart layout**. Levels reach the phone only when the desktop browser **saves the
layout**. If auto-apply silently stalls, no apply means no layout save, so the phone loads a
stale/empty layout.

Levers (nothing to fix, operational):
- The widget already saves the layout after every apply (`saveLayout()` at end of
  `applyToChart`). Verified live: the header read "All changes saved" right after auto-apply.
- **"Push now"** forces apply + layout save every time. It is the manual "refresh my phone"
  button. Tell Elroy to use it whenever the phone looks stale, then reopen the chart on mobile.
- v3.35's `refreshed`/`checked`/pending signals are what make a silent stall visible so he knows
  when to Push.
- Note: the live layout is a **two-chart split** (NES1! + NNQ1!); the mobile app shows one chart
  at a time, which can also make a split layout look wrong on the phone.

## Build & deploy (from memory `atas-platform-facts`)

- **ATAS indicator** (all custom indicators compile into one DLL): build Release, then
  `cp indicators/bin/Release/net10.0/AtasOnSteroids.dll "~/Library/Application Support/ATAS/Indicators/"`,
  then **fully restart ATAS** (it caches loaded DLLs). Avoid Newtonsoft.Json in indicators
  (silent fail); serialize numbers with `CultureInfo.InvariantCulture` (comma-decimal locale).
- **Trading-journal backend** (serves the levels the userscript fetches at `localhost:3001`):
  runs via launchd. Restart: `launchctl kickstart -k gui/$(id -u)/com.tradingjournal.backend`.
  Logs: `/tmp/tradingjournal-backend.log`. Must be running for the widget to sync.
- **Userscript** lives in Tampermonkey (Brave). The running copy is already v3.35; the repo now
  matches. To update: paste `tradingview-sync/atas-levels.user.js` into the Tampermonkey editor
  and save (Cmd+S). The editor's "could not be translated from: null" lint is a harmless
  metadata notice tied to the script name, not a code error.
- **Sync trigger**: ATAS writes `~/Library/Application Support/ATAS/Workspaces2/*.aws` (plain
  JSON) on workspace save; the backend reads that, the userscript polls every 15s.
